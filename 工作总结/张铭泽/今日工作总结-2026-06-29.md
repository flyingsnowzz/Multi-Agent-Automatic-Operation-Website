# 今日工作总结 — 2026-06-29

## 1. Redis 流水线改造

今天重点完成了生产链路从单进程 Pipeline 向 Redis Streams Worker 架构的迁移验证与修复。

### 1.1 新增 Redis Stream 基础设施

新增统一 Redis 工具模块：

| 文件 | 作用 |
|------|------|
| `scripts/redis_pipeline.py` | 定义 Redis Stream 名称、Consumer Group、连接、ack、pending 恢复等基础方法 |
| `scripts/redis_fill.py` | 从 MySQL `crawler_news_main` 灌入文章到 `pipeline:scoring` |
| `scripts/redis_feeder.py` | 常驻轮询 MySQL 新文章，自动推入 Redis |
| `scripts/run_redis_workers.py` | 一键启动 feeder + scoring/quality/rewrite/publish workers |

当前 Redis 队列分为四段：

```text
pipeline:scoring  → worker_scoring.py
pipeline:quality  → worker_quality.py
pipeline:rewrite  → worker_rewrite.py
pipeline:publish  → worker_publish.py
```

### 1.2 Worker 拆分

新增 4 个常驻 worker：

| Worker | 职责 |
|--------|------|
| `worker_scoring.py` | 批量 AI 评分，写入审计表，推送 Quality 队列 |
| `worker_quality.py` | 调用 QualityAgent，按分数分流 rewrite/publish |
| `worker_rewrite.py` | 调用 ResearchAgent + WriterAgent + EditorAgent，生成/编辑文章 |
| `worker_publish.py` | 调用 SEOAgent + ImageAgent + CMSAgent，完成发布预检或真实发布 |

同时补充了 pending 恢复能力，worker 重启后可以继续处理 Redis 中未完成的消息。

## 3. Rewrite 通过率问题排查

发现 Redis rewrite worker 与旧单流程 `run_production.py` 调用逻辑不一致，是改写通过率明显下降的主要原因。

### 3.1 问题原因

Redis worker 原逻辑：

```python
ResearchAgent().execute(..., mode="mock")
QualityAgent().score_article(..., if_ai_generated=True)
```

旧单流程逻辑：

```python
ResearchAgent().execute_direct(..., mode="live")
WriterAgent 注入 research_prompt
QualityAgent().score_article(...)  # 不加 if_ai_generated=True
```

差异导致：

- Research 材料质量下降
- Writer prompt 没有完全复用旧链路
- QualityAgent 启用了生成文 AI 味惩罚权重

### 3.2 修复

已将 `worker_rewrite.py` 改为与旧单流程一致：

- 使用 `ResearchAgent.execute_direct(..., mode="live")`
- 注入 `research_prompt`
- 复评时不传 `if_ai_generated=True`
- 支持完整正文输入，避免只用几十字 description 改写

## 5. SEOAgent 关键词修复

### 5.1 问题

`KeywordAnalyzerV2` 之前会把整句标题当成关键词，例如：

```text
2025全球商教大变局：MBA“祛魅”，专硕“封神”？深度解读与中国启示
```

原因是 V2 返回结果里没有正确透出 `keywords` 字段，SEOAgent fallback 到 `primary_keyword`，而 `primary_keyword` 往往就是标题。

### 5.2 修复

更新：

| 文件 | 修复 |
|------|------|
| `agents/seo_agent/tools/keyword_analyzer_v2.py` | 增加关键词归一化、jieba 分词、停用词过滤、短词输出 |

修复后关键词倾向于输出词汇而不是短句：

```text
全球、商教、MBA、专硕、调剂、院校、复试、科大
```

```bash

```

默认行为：

- 首次启动记录当前最大 article id
- 之后只处理新增文章
- 避免上线时把历史数据重复灌入 Redis

支持参数：

```bash
--feed-interval 60
--feed-limit 100
--feed-from-id 2020
--feed-existing
```

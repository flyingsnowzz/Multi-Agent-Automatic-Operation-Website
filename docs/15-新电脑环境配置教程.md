# 新电脑环境配置教程

这份文档用于在另一台电脑从零跑起 LangGraph 正式流水线。

当前主链路是：

```text
MySQL crawler_news_main
  -> run_langgraph_batch.py
  -> LangGraph ArticleGraphState
  -> Scoring / Quality / Rewrite / SEO / Image / CMS nodes
  -> CMS dry-run 或真实发布
```

## 1. 准备基础软件

推荐方式：MySQL 用 Docker 跑，LangGraph runner 在本机虚拟环境或 Docker pipeline 容器里跑。

推荐版本：

- Python 3.10+
- Docker Desktop
- Git
- MySQL 客户端可选；如果不装，可以直接用 Docker 容器里的 `mysql` 命令

macOS 常用安装：

```bash
brew install python git
```

启动基础服务：

```bash
docker compose up -d mysql
```

## 2. 拉代码和创建 Python 环境

```bash
git clone https://github.com/flyingsnowzz/Multi-Agent-Automatic-Operation-Website.git
cd Multi-Agent-Automatic-Operation-Website

python3 -m venv .venv
source .venv/bin/activate
python -m pip install -U pip
pip install -r requirements.txt
```

Windows PowerShell：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -U pip
pip install -r requirements.txt
```

## 3. 配置环境变量

复制模板：

```bash
cp .env.example .env
```

至少要配置：

```bash
MYSQL_HOST=localhost
MYSQL_PORT=3306
MYSQL_USER=root
MYSQL_PASSWORD=change-me-mysql
MYSQL_ROOT_PASSWORD=change-me-mysql
MYSQL_DATABASE=multi_agent_cms
RESEARCH_MYSQL_DATABASE=research_article_data

ARTICLE_SCORING_API_KEY=...
ARTICLE_SCORING_MODEL=deepseek-chat
ARTICLE_SCORING_BASE_URL=https://api.deepseek.com

WRITER_AGENT_API_KEY=...
WRITER_AGENT_MODEL=deepseek-chat
WRITER_AGENT_BASE_URL=https://api.deepseek.com

CMS_ENABLE_REAL_PUBLISH=false
```

这里的 `MYSQL_DATABASE` 是**一个数据库/库名**，不是单张表名。LangGraph 正式流水线会在这个库里读取爬虫文章表和正文分片表，并写入审计表。默认配置是：

```text
CRAWLER_MAIN_TABLE=crawler_news_main
CRAWLER_SHARD_PREFIX=crawler_news_
CRAWLER_SHARD_COUNT=5
PIPELINE_AUDIT_TABLE=pipeline_audit
```

如果接现有 CMS 数据库，例如 PHP 配置里的 `dbname => zyxw`，就把 `MYSQL_DATABASE=zyxw`，再按真实表名覆盖 `CRAWLER_*`。例如测试服当前是一个库 `zyxw`，里面有多张文章表：

```bash
MYSQL_DATABASE=zyxw
CRAWLER_MAIN_TABLE=zyxw_college_news
CRAWLER_SHARD_PREFIX=zyxw_college_news_
CRAWLER_SHARD_COUNT=10
CRAWLER_USAGE_STATUS_COLUMN=
```

`CRAWLER_USAGE_STATUS_COLUMN=` 留空表示现有源表没有 used 标记列，LangGraph 不会读取或写入这个列。测试环境更推荐单独建 `multi_agent_cms`，避免污染现有站点库。

如果需要真实生图，再配置：

```bash
COZE_JWT_TOKEN=...
```

如果需要真实发布，再配置 CMS：

```bash
CMS_API_URL=https://your-cms-domain.com/api
CMS_API_KEY=...
CMS_ENABLE_REAL_PUBLISH=true
```

真实发布还需要启动命令显式加 `--publish`，否则仍然是 dry-run。

## 4. 准备 MySQL 数据库

推荐使用 Docker MySQL：

```bash
docker compose up -d mysql
docker compose ps mysql
```

第一次启动时，`docker/mysql/init/01-create-databases.sql` 会自动创建：

- `multi_agent_cms`
- `research_article_data`

如果要手动确认：

```bash
set -a
source .env
set +a

docker compose exec -T mysql \
  mysql -uroot -p"$MYSQL_ROOT_PASSWORD" \
  -e "SHOW DATABASES LIKE 'multi_agent_cms'; SHOW DATABASES LIKE 'research_article_data';"
```

如果你不用 Docker MySQL，而是使用本机或远程 MySQL，则手动创建数据库：

创建数据库。注意这里创建的是库，不是单表：

```sql
CREATE DATABASE IF NOT EXISTS multi_agent_cms
  DEFAULT CHARACTER SET utf8mb4
  DEFAULT COLLATE utf8mb4_0900_ai_ci;

CREATE DATABASE IF NOT EXISTS research_article_data
  DEFAULT CHARACTER SET utf8mb4
  DEFAULT COLLATE utf8mb4_0900_ai_ci;
```

如果你有爬虫数据 dump，导入到 `multi_agent_cms`：

```bash
set -a
source .env
set +a

docker compose exec -T mysql \
  mysql -uroot -p"$MYSQL_ROOT_PASSWORD" "$MYSQL_DATABASE" \
  < crawler_data.sql
```

测试数据可用：

```bash
set -a
source .env
set +a

docker compose exec -T mysql \
  mysql -uroot -p"$MYSQL_ROOT_PASSWORD" "$MYSQL_DATABASE" \
  < crawler_data_test.sql
```

导入默认测试数据后应至少有这些业务表：

- `crawler_news_main`
- `crawler_news_0`
- `crawler_news_1`
- `crawler_news_2`
- `crawler_news_3`
- `crawler_news_4`

如果接现有 CMS 库，业务表名可以不是上面这些，但必须用 `CRAWLER_MAIN_TABLE`、`CRAWLER_SHARD_PREFIX`、`CRAWLER_SHARD_COUNT` 配好。`pipeline_audit` 不属于爬虫原始数据，它由下面的迁移脚本创建，用于保存 LangGraph 每篇文章的评分、重写、SEO、图片和 CMS dry-run/发布状态。

## 5. 执行数据库迁移

按顺序执行：

```bash
set -a
source .env
set +a

docker compose exec -T mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" "$MYSQL_DATABASE" < sql/create_pipeline_audit.sql
docker compose exec -T mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" "$MYSQL_DATABASE" < sql/alter_pipeline_audit_seo_meta.sql
docker compose exec -T mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" "$MYSQL_DATABASE" < sql/alter_crawler_article_usage_status.sql
docker compose exec -T mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" "$MYSQL_DATABASE" < sql/alter_pipeline_audit_drop_large_audit_payloads.sql
```

Research/Writer 输出库：

```bash
docker compose exec -T mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" < sql/create_research_article_candidates.sql
docker compose exec -T mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" < sql/create_writer_article_outputs.sql
```

验证表是否存在：

```bash
docker compose exec -T mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" "$MYSQL_DATABASE" -e "
SHOW TABLES LIKE 'pipeline_audit';
SHOW COLUMNS FROM crawler_news_main LIKE 'image';
SHOW COLUMNS FROM pipeline_audit LIKE 'seo_meta_%';
"
```

## 6. Dry-run 跑通 LangGraph 正式流水线

当前正式入口是 LangGraph。先只跑一批，确认 MySQL、模型、审计日志都正常：

```bash
python3 scripts/run_langgraph_batch.py --feed --limit 10
```

长期无人值守 dry-run。这个命令会放到后台运行，不占用当前终端，运行日志写到 `logs/langgraph_batch.log`：

```bash
make run
```

查看、停止、确认状态：

```bash
make logs
make status
make stop
```

`--production` 会开启 feeder、循环运行、审计落库和 used 标记，但 CMS 仍然是 dry-run。

如果只想调少量文章：

```bash
python3 scripts/run_langgraph_batch.py --ids 1961 --limit 1 --persist-audit
```

## 7. 真实发布

确认 `.env`：

```bash
CMS_API_URL=...
CMS_API_KEY=...
CMS_ENABLE_REAL_PUBLISH=true
```

启动：

```bash
CMS_ENABLE_REAL_PUBLISH=true LANGGRAPH_ARGS=--publish make run
```

## 9. 常见问题

### MySQL 连接失败

检查 `.env` 里的：

- `MYSQL_HOST`
- `MYSQL_PORT`
- `MYSQL_USER`
- `MYSQL_PASSWORD`
- `MYSQL_DATABASE`

用命令直接试：

```bash
docker compose ps mysql
docker compose exec -T mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" "$MYSQL_DATABASE" -e "SELECT 1;"
```

### 没有文章进入流水线

检查：

- `crawler_news_main` 是否有数据
- `article_usage_status` 是否都已经是 `used`
- feeder 是否用了 `--bootstrap-latest`
- 是否需要改用 `--feed-existing` 跑历史数据

### 图片没有复用原封面

原封面来自：

```sql
crawler_news_main.image
```

检查：

```bash
docker compose exec -T mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" "$MYSQL_DATABASE" -e "
SELECT id, title, image
FROM crawler_news_main
WHERE image IS NOT NULL AND image <> ''
LIMIT 5;
"
```

当前发布阶段封面优先级：

```text
pipeline_audit 已有封面 > crawler_news_main.image 原封面 > ImageAgent 重新生成
```

### prompt 日志为空

`logs/prompt_audit/*.jsonl` 只有新 worker 任务跑过之后才会写入。刚迁移完、还没跑流水线时为空是正常的。
